# 台灣區域地殼變形比較研究 — GNSS 同震位移分析

## 專案目標

> 想下載本專案重現分析流程(安裝 PPP-AR、修正已知 bug、下載資料、跑腳本)的人,請先看 **[SETUP.md](SETUP.md)**,裡面有完整的環境建置教學跟踩坑記錄。

比較台灣東、南、北三個構造環境不同的地震案例,利用 GNSS 座標時間序列偵測同震位移訊號,評估不同斷層型態/構造背景下地表變形訊號的可偵測性。

延續自先前完成的地震目錄分析工具(Gutenberg-Richter 定律分析、多種 Mc 估計法、時期比較),本專案把分析範疇從地震目錄延伸到 GNSS 地殼變形,建立跨區域比較框架。

## 三個區域案例

| 區域 | 地震 | 規模 | 日期 | 狀態 |
|---|---|---|---|---|
| 南 | 美濃地震 | M6.6 | 2016/02/06 | ✅ 完成,含自行 PPP-AR 處理 + NGL 交叉驗證 |
| 東 | 花蓮地震 | M7.1-7.3 | 2024/04/03 | ✅ 完成(NGL 資料為主) |

## 方法論總覽

### 資料處理管線(自行 PPP-AR 處理)

```
本機 RINEX 觀測檔(CWA GDMS 下載)
    → PRIDE PPP-AR(本機安裝,透過 Claude Code + Miniforge/conda-forge 裝 gfortran,因 sudo 權限異常)
    → 每日 ITRF 座標(X/Y/Z, ECEF)
    → ITRF2014 → ITRF2020 轉換(影響約 2-3mm,相對訊號量級可忽略)
    → ECEF → ENU 轉換(以震前參考點為基準,pyproj/pymap3d)
    → 震前多天平均 vs 震後/震當天位移量
```

### 引用聲明

本專案使用 NGL(Nevada Geodetic Laboratory)提供的 GNSS 座標時間序列資料。依 NGL 網站使用條款,使用其產出資料需引用:

> Blewitt, G., W. C. Hammond, and C. Kreemer (2018), Harnessing the GPS data explosion for interdisciplinary science, Eos, 99, https://doi.org/10.1029/2018EO104623

### 交叉驗證資料源:NGL(Nevada Geodetic Laboratory)

NGL 提供全球 GNSS 站的獨立處理結果(24 小時 final solution, tenv3 格式),可作為自行 PPP-AR 結果的交叉驗證,或在時間有限、無法自行處理時作為主要資料源。

**重要:GNSS_IES 站在 NGL 上的代碼可能與 GDMS 原始代碼不同**,需要用座標比對確認是同一站(見 `scripts/ngl_timeseries.py` 裡的 `STATION_CODE_MAP`)。已確認的對應:

|---|---|
| PAOL | PAO1 |
| S106 | T106 |
| YENC | YEN2 |
| SCHN | SCH7 |

### 主要結果(CWA GNSS 網,自行 PPP-AR)

- 8 站候選,47 個站天全部成功處理(0 失敗)
- 5 站(GAIS, SHWA, LGU2, MLO1, SAND)在正確的地震日期(02/05→02/06)偵測到數十毫米量級的同震跳動,獨立於 NGL 官方表格自行偵測

- 實際成果檔案已收錄於 `results/meinong_cwa/`:6 站 ENU 時間序列圖(GAIS/SHWA/LGU2/LIKN/MLO2/SNDI)為 **NGL 版本**(圖標題已標明);互動式座標時間序列報告(`meinong_gnss_report.html`)則是**自行 PPP-AR 處理結果**,兩者資料來源不同,引用時要分清楚。從 NGL 版本的圖可以看出:GAIS/SHWA/LGU2/MLO2(即 MLO1)/SNDI(即 SAND)五站在 2016-02-06 都有清楚的階梯狀同震跳動,方向與幅度互相吻合;**LIKN 站的時間序列全程呈現鋸齒狀劇烈震盪(數十 mm 級雜訊,震前震後皆同),完全看不出同震訊號被雜訊淹沒的模式,直接支持排除這站的判斷**;LGU2 因站點記錄從 2016-02-02 才開始,震前只有 4 天資料可用,判讀時需留意基準點樣本數較少 —— **⚠️ 修正**:上面「5 站有清楚跳動」是單純看圖形狀的判斷,後續用統計顯著性檢定(見下方「統計顯著性檢定結果」段落)發現 **SNDI 其實大部分分量不顯著**,不應算在高信度那組裡,以下方的檢定結果為準

### PPP-AR 批次處理踩坑記錄(供之後其他區域案例參考)

1. **8 小時「卡住」的假象**:`nohup python3 script.py > log 2>&1 &` 這種寫法,Python 的 `print()` 輸出在重導向到檔案時預設是整塊緩衝(full buffering),不是逐行輸出,導致進度訊息長時間卡在記憶體緩衝區沒寫進 log 檔案,看起來像沒有進度,其實程式一直在正常跑。用 `python3 -u`(unbuffered)可避免。

2. **`subprocess.run(timeout=...)` 沒有真的生效**:pdp3 內部用 `echo "$cmd" | bash` 呼叫子程序,會產生孫行程佔用輸出管線;Python 的 timeout 機制在這種情況下會卡在等待管線關閉,即使設定的 timeout 時間到了也不會確實觸發,需要改成對整個 process group 送出終止訊號(而非單一 PID)才能真正生效。

3. **timeout 時長的抉擇**:大部分站天約 37-51 分鐘可完成,但震當天(訊號受同震擾動影響)可能需要超過 2 小時才能收斂(更多輪 redig 迭代)。過短的 timeout(如 40-50 分鐘)會誤殺震當天這種最關鍵的資料。最終決定用 3 小時的寬鬆 timeout,平衡「不誤殺合理的長時間收斂」與「防止真正無限卡死」兩種需求。**重要修正**:後續實測發現「地震當天比較慢」不是通則(DONA 站的震當天只花了正常時間 40 分鐘),只有 LNCH 站的震當天特別慢 —— 比較可能是該站當天資料品質本身有特殊狀況(雜訊、cycle slip),不是所有站的震當天都會慢。

4. **背景執行的環境限制**:用 Claude Code(VS Code)在 Windows/WSL 環境下,Claude Code 自己的背景執行機制會在終端機/session 關閉時中斷,必須改用獨立終端機的 `nohup ... &` 執行長時間批次工作;另外作業系統的睡眠/休眠也會中斷 nohup 工作,需要在長時間批次執行期間關閉睡眠設定。若執行中途需要暫時斷網或做其他事,可用 `kill -STOP <PID>` 暫停(而非終止)整個 process group,之後用 `kill -CONT <PID>` 恢復,不會遺失已完成的進度。

## 東部案例:花蓮地震(2024/04/03, M7.1-7.3)

### CWA GNSS 網(主要分析)

同震位移直接取自 NGL 的**官方預算 offset 表格**(不需自行 PPP 處理),原訂 11 站候選中 6 站(YENL, SHUL, DNFU, TUNM, HUA3=HUAL, SLI1=SLIN)有涵蓋;NDHU, PEPU, CHNT, FENP, HRGN 5 站 NGL 未涵蓋。**DNFU 後續已排除**(資料觀測不規律、震當天無資料、統計檢定窗口無法跟其他站一致,詳見下方排除紀錄),最終案例為 5 站(YENL, SHUL, TUNM, HUA3=HUAL, SLI1=SLIN)。

**方法學重要提醒**:對於位移量較小/雜訊較大的站,用簡單的「NGL 每日 tenv3 時間序列震前/震後平均」計算出的位移量,不一定跟 NGL 官方 offset 表格的數字吻合 —— **最終引用的位移數字應以官方 offset 表格為準**,自行畫的時間序列圖只適合拿來看趨勢走向/視覺化,不是拿來算最終位移量的依據。

**DNFU 站排除紀錄**:DNFU 原本是候選站之一,但這站的觀測記錄很不規律(缺漏很多天),且**震當天(4/3)完全沒有觀測資料**,做統計顯著性檢定時只能改用震後2天(4/5)、且震前樣本橫跨較長時間,窗口跟其他站不一致,沒辦法放在同一標準下比較;檢定出來的震前標準誤差也遠大於其他站(East 18.85mm、Up 22.17mm,其他站多在1-4mm),顯示這站資料品質本身就差。比照之前排除 S169 的處理原則(問題無法在合理時間內解決、且會破壞跨站比較的一致性),**決定直接排除 DNFU,不列入最終的花蓮 CWA 網分析與跨區域比較**。

### 重要發現:NGL 資料的系統性截止日期(2024/4/3)

已確認(逐站查證 NGL 網站頁面)**所有 GNSS_IES 站**(不論是花蓮周邊或先前分析過的美濃周邊站:PAOL/S106/S169/DONA/WLIP)在 NGL 上的資料都在 **2024/04/03 前後統一中斷**。這是 NGL 收到 GNSS_IES 資料流的**系統性截止**,與地震本身無關,不是個別測站因地震受損而斷訊。

## 北部案例:大屯火山群地震(2014/02/12, M4.2)

### CWA GNSS 網

原始 6 站候選(ANBU, ZUZH, TANS, WUKU, WAN2, WALI)中 4 站(ANBU, ZUZH, WAN2, WALI)在 2014 年尚未啟用,僅剩 TANS 與 WUKU 兩站可用。決定保留這個案例(而非改選規模較小、較近期的大屯區地震),作為跨區域比較的一部分。

**重要 bug 修復**(本機 PRIDE PPP-AR 安裝,`~/.PRIDE_PPPAR_BIN`):

1. **pdp3 跨日期進位捨入錯誤**(路徑:`~/.PRIDE_PPPAR_BIN/pdp3`,共 3954 行 bash script,修改前備份於 `pdp3.bak`)。實際 diff:
   ```diff
   876c876
   <     ts_sec=$(echo "$hms_s" | awk -F: '{print $1*3600 + $2*60 + $3}')
   ---
   >     ts_sec=$(echo "$hms_s" | awk -F: '{printf("%.7f", $1*3600 + $2*60 + $3)}')
   878,880c878,880
   <     print int((ts + b - 1e-9)/b)*b
   ---
   >     v=int((ts + b - 1e-9)/b)*b
   >     if (v>=86400) v=int(ts/b)*b
   >     print v
   ```
   修正重點:原本的時間捨入計算在 epoch 時間非常接近午夜時,會捨入到 86400 秒(也就是隔天的 24:00:00,實際上應該是隔天 00:00:00),導致 spp 崩潰。修正後改用更高精度的 `printf` 計算秒數,並加上明確的邊界檢查(`if (v>=86400) v=int(ts/b)*b`),避免捨入結果超過一天的秒數上限。

2. **redig 的 Fortran 格式字串錯誤**(路徑:`~/src/PRIDE-PPPAR/src/redig/get_redig_args.f90` 第 182 行,git 追蹤但尚未 commit 的修改;對應編譯後執行檔在 `~/.PRIDE_PPPAR_BIN/redig`,同樣有 `.bak` 備份)。實際 diff:
   ```diff
   - read (resfil(i:), '(4xi4i3)', err=200) jy, jdoy
   + read (resfil(i:), '(4X,I4,I3)', err=200) jy, jdoy
   ```
   修正重點:原本的格式字串 `'(4xi4i3)'` 缺少逗號分隔各個格式描述符(應為 `4X,I4,I3`,分別代表跳過4個字元、讀取4位數整數、讀取3位數整數),Fortran 編譯器可能誤判格式導致提早中止讀取(在 jmp=400 提早結束,而非完整收斂)—— 觸發時可能造成約 1.2-1.7cm 的座標誤差。
   - 已確認美濃案例的 47 個站天**不受此 bug 影響**(在發現此 bug 前就已全部完整收斂;此 bug 是機率性的,只在接收儀第一個 epoch 的時鐘偏移剛好跨過午夜整數捨入時才會觸發)。

## 統計顯著性檢定結果

用 `scripts/statistical_significance.py`(震前多天平均+標準誤差 vs 震後/震當天 formal uncertainty,合併後算 t 值)檢驗各站的同震跳動是否為真訊號,取代單純看圖形狀的判斷。

### 檢定的統計原理

這是一個**雙尾 t 檢定(two-tailed t-test)**,用來判斷震後(或震當天)測到的座標跳動,是真實的地表位移,還是只是雜訊造成的正常波動。

**虛無假設 H₀**:震後座標與震前平均座標沒有真正的差異——觀察到的差值只是隨機雜訊造成的正常波動,測站的真實位置其實沒有改變。

**對立假設 H₁**:震後座標與震前平均座標確實不同——地震造成了真實的地表位移,差值不只是雜訊。

**t 值計算**:
```
t = |震後值 − 震前平均| / 合併不確定度
```

其中合併不確定度 = √(震前標準誤差² + 震後當日 formal uncertainty²)(震前標準誤差 = 震前樣本標準差 / √震前天數)。t 值越大,代表這個差值相對於正常波動範圍越大、越不像是雜訊。

**判斷方式**:因為震前樣本數通常只有 4-7 天(樣本數小),不能直接套用常態分布的固定門檻(如 3-sigma、2-sigma),而是改用 **t 分布**,依實際自由度(df = 震前天數 − 1)動態算出對應的臨界值:
- t 值 ≥ 99.7% 信心水準對應的臨界值(雙尾各留 0.15% 尾巴,加總才是 99.7%)→ **顯著**,拒絕虛無假設,可信為真訊號
- t 值介於 95% 與 99.7% 信心水準臨界值之間 → **邊界**,證據不夠強,需謹慎
- t 值 < 95% 信心水準對應的臨界值 → **不顯著**,現有資料不足以拒絕虛無假設(不代表「一定沒有位移」,只代表「無法排除這只是雜訊」)

自由度越小(震前樣本天數越少),臨界值越高、判斷越保守,避免用太少的資料就輕易宣稱「有訊號」。p 值(腳本輸出裡也有印出)則是「假設 H₀ 為真時,觀察到這麼極端差值的機率」,p 值越小代表越有理由拒絕虛無假設。

**重要方法修正**:最初版本用固定的 3-sigma/2-sigma(常態分布)當門檻,但震前樣本數通常只有 4-7 天,樣本數這麼小應該用 **t 分布**、依實際自由度(df = 震前天數 - 1)動態算臨界值,而不是套用常態分布的固定門檻 —— 樣本數越小,t 分布的臨界值比 3.0/2.0 高出更多(例如 df=5 時 99.7% 信心水準對應臨界值是 5.4,不是 3.0)。改用 t 分布後,原本好幾個「顯著」或「邊界」的站,結果變得更保守,以下是修正後的最終結果:
